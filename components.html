ALCWARE · Sistema visual

Design System cross-product

Fuente de verdad visual para las aplicaciones ALCWARE. El documento separa tokens base, roles, estados y componentes para que una persona, un desarrollador u OpenDesign puedan identificar qué es cada elemento, cuándo se usa y qué valores son canónicos.

OpenDesign Ready · V1
00 · Principios

Cómo leer este Design System

Cada componente muestra nombre canónico, propósito, variantes y estados. No se deben deducir roles únicamente por el color visual: el nombre del token y su uso documentado son la referencia.

1 · Foundation tokensValores crudos: Primary, Neutral y familias de color.
2 · Role tokensUso: background, surface, border, text, action, status.
3 · Interaction statesDefault, hover, selected, focus, disabled y loading.
4 · ComponentsBotones, filtros, tablas, cards, formularios y overlays.
Regla de lectura para OpenDesign: el texto y las etiquetas del documento son deliberadamente explícitos. “Primary 600” significa un tono de la familia Primary; “Success 500” significa un tono de estado semántico; “Surface” es un rol estructural y no una familia de color.

02 · Foundations

Color System

El sistema de color se divide en cuatro capas: Primary para marca e interacción; Neutral para texto y estructura; Semantic para significado; y Auxiliary para categorías y visualización de datos. Esta separación es obligatoria.

Cómo interpretar los coloresAntes de usar un HEX, identifica la familia y el rol
Primary / TealMarca ALCWARE, CTA principal, navegación activa, selección, foco y enlaces relevantes.
NeutralTexto, fondos, cards, divisores, bordes, placeholders y jerarquía estructural.
SemanticSuccess, Warning y Danger. Solo comunican significado: éxito, atención o error/riesgo.
AuxiliaryBlue, Cyan, Orange, Violet y Pink. Categorías, fases, series de gráficos y diferenciación secundaria.
Regla rápida para familias de 3 tonos: 100 = fondo suave · 500 = acento / punto / gráfico · 700 = texto / icono. Primary y Neutral tienen una escala más amplia porque también construyen navegación, foco, texto, bordes y superficies.

Reglas de colorDo / Don't
Teal comunica interacción

Úsalo para CTA, activo, seleccionado, focus y links relevantes. No colorees todo el contenido.

Semantic conserva significado

Green = éxito, Amber = atención, Coral = error/riesgo. No intercambiar por estética.

Auxiliary diferencia, no manda

Blue, Cyan, Orange, Violet y Pink sirven para categorías, fases y series, nunca como CTA principal.

Neutral construye la estructura

Texto, page background, cards, headers de tabla, borders y metadatos.

Un nombre = un valor canónico

Primary 800 siempre es #006B76. White siempre es #FFFFFF. Neutral 900 siempre es #102124.

Primero rol, luego HEX

En implementación usa tokens. Evita copiar HEX aislados si existe un token de rol.

13 · Implementación

Reglas canónicas

Estas reglas resuelven conflictos cuando una pantalla concreta no esté documentada todavía.

1. Una sola familia Primary

Los tonos Teal se llaman Primary 900/800/700/600/500/300/200/100/50. White y Neutral jamás deben renombrarse como Primary.

2. Role tokens sobre HEX

En código de producto, priorizar --surface, --border, --text, --action-* y --interaction-* sobre valores crudos.

3. Entidad principal más fuerte

Nombre/ID o elemento principal con más peso; compañía, ramo, fecha y metadata con menor jerarquía.

4. Primary ≠ decoración

Teal identifica interacción y marca. No convertir grandes superficies o todo el body text en teal.

5. Danger solo para riesgo

Coral para errores, vencidos, no contratado o acciones destructivas. No usarlo para “dar variedad”.

6. Estados completos

Todo control interactivo debe considerar default, hover, focus y disabled; selected/open cuando corresponda.
